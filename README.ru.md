# Отзывы об AnnotaryCat

[English](README.md) · [Китайский (упрощённый)](README.zh-CN.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Português](README.pt.md) · **Русский**

В этом репозитории собираются сообщения об ошибках и предложения новых функций для AnnotaryCat.

> **Всё, что здесь публикуется, открыто для всех.** Любой может прочитать issue и скачать вложения. Не публикуйте пароли, API-токены, SSH-ключи, а также изображения и данные, которыми вы не имеете права делиться.

## 1. Создайте диагностический пакет

Диагностический пакет — это файл `.zip`, который AnnotaryCat создаёт на вашем компьютере. В нём:

- `system.json`: версия AnnotaryCat, операционная система, процессор, видеокарта и настройки (без паролей, токенов и путей к рабочим пространствам);
- `logs/`: журналы работы за последние несколько дней;
- `crashes/`: записи о сбоях, если AnnotaryCat завершился некорректно.

В журналах записываются только названия команд, коды ошибок и время выполнения. В них нет данных проектов, разметки, содержимого файлов, значений параметров и паролей. Домашняя папка отображается как `~`.

Язык интерфейса AnnotaryCat по умолчанию — английский. Вам понадобятся эти пункты меню на английском:

| Пункт меню | Что делает |
|---|---|
| **Help › Send a problem report…** (Справка › Сообщить о проблеме…) | **Рекомендуется.** Создаёт пакет, открывает в браузере новую issue в этом репозитории с уже заполненными заголовком и шаблоном и показывает, где лежит пакет. |
| **Help › Export diagnostics…** (Справка › Экспортировать диагностический пакет…) | Сохраняет пакет в выбранное место. После этого откройте [новую issue](../../issues/new) самостоятельно. |

Прежде чем прикрепить пакет, просмотрите его: в диалоговом окне можно открыть каждый файл. Если там есть то, что не должно стать публичным (например, название папки), удалите этот файл из архива или не прикрепляйте пакет и опишите проблему словами.

**Если AnnotaryCat не запускается**, прикрепите вместо пакета файлы из папки журналов (файлы `annotarycat-*.log` и `crash-*.log`, упакованные в zip):

| Система | Папка журналов |
|---|---|
| Windows | `%LOCALAPPDATA%\AnnotaryCat\logs` |
| macOS | `~/Library/Logs/AnnotaryCat` |
| Linux | `$XDG_STATE_HOME/annotarycat/logs` (обычно `~/.local/state/annotarycat/logs`) |

Пакеты, созданные через Send a problem report…, хранятся в папке `reports` внутри папки журналов.

## 2. Заполните issue

**Заголовок:** `[Bug] AnnotaryCat <версия> (<система>): <кратко о проблеме>`

Например: `[Bug] AnnotaryCat 0.2.0 (windows-x86_64): экспорт в COCO останавливается на 50%`. Версию можно посмотреть в Help › About AnnotaryCat (Справка › О программе).

**Текст:** используйте этот шаблон; Send a problem report… заполняет его за вас. Заголовки разделов оставьте на английском, а сам текст пишите на любом языке.

```markdown
## Description

Что пошло не так, в одном-двух предложениях.

## Steps to reproduce

1.
2.
3.

## Expected behavior

Что вы ожидали увидеть.

## Actual behavior

Что произошло на самом деле, включая показанное сообщение об ошибке.

## Environment

- Version:
- OS:
- Diagnostics bundle: (перетащите сюда файл .zip)
```

Затем **перетащите файл `.zip` в текст**, чтобы прикрепить его, ещё раз всё проверьте и отправьте.

Советы:

- Одна проблема — одна issue. Сначала поищите среди [существующих issue](../../issues); если ваша проблема уже описана, добавьте комментарий.
- Снимки экрана помогают, если на них нет ничего личного.
- Укажите, происходит ли это каждый раз или только иногда.

## 3. Предложения функций

Заголовок: `[Feature] <что вы хотели бы>`. В тексте опишите, что вы хотите сделать, зачем и как вы делаете это сейчас. Диагностический пакет не нужен.
